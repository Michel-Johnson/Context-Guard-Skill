# 可靠性与 CI 深度 Review

范围：最新 `main` 与本轮可靠性分支的差异。职责包括找问题、用正式测试证明问题，并只对已经确认的工程缺陷实施修复；无法由本地自动化证明的事项继续留在 `CI_todo.md`。

## 已确认并处理

| 问题 | 风险 | 处理与证据 |
| --- | --- | --- |
| Required CI 没有完整汇总所有关键 job，测试文件依赖手工登记 | 漏跑测试仍可能显示绿色 | 自动发现 `*.test.mjs`，Required 汇总安全、功能、最低版本、安装、浏览器、客户端和站点 |
| 各 Agent 新增的测试没有统一分类和质量底线 | 测试入口、命名、跳过规则不断分叉 | `tests/test-manifest.json` 与自动治理检查；责任边界见 `docs/test-governance.md` |
| Hook/CLI 对同一 Session 状态并发读改写 | 丢 signal、TODO、归档状态 | 进程锁串行、崩溃释放、损坏文件失败关闭；24 并发写入正式测试 |
| Session Map 完成后仍可继续写 | 已合并分支与历史 Session 混在一起 | 发布 Main 后原子关闭并删除 Session Map；旧 ID 新写入返回 410，保留审计历史和回执 |
| 同步锁和 checkpoint 边界不足 | 崩溃遗留锁、检查动作误发布草稿 | 共享文件锁、独立 checkpoint；重连和 SSE 游标恢复测试 |
| 同步进程收到停止信号仍等待 SSE 超时 | 重启最多卡住 60 秒 | 停止时主动取消网络请求；重启后从持久游标补事件 |
| Bad Case 需要连续写多个本地文件再写 Map | 中途崩溃留下半条记录或已挂 Map 未收口 signal | 持久事务日志和幂等重放；occurrence/fix 均做进程中断测试 |
| Cloud 接受查询字符串中的 API token | URL、历史和日志泄漏凭据 | API token 只允许 Authorization header；浏览器一次性交换入口单独保留 |
| 工作台 6000 多行结构、样式、演示数据和逻辑耦合 | Review 困难，改一处同时影响三种发布面 | 拆成 HTML/CSS/fixtures/app，并通过本地、Cloud、官网三条链路 |
| 产品默认数据伪装成用户记忆 | 用户误以为是自己的历史记录 | 消融后删除硬编码记忆；31 项浏览器检查通过 |

## 仍然存在的限制

- 模型对“这是 TODO 还是 Bad Case”“测试证据是否真实”“是否应新建节点”的语义判断，不能靠字段必填校验证明正确；需要独立 Review 或人工抽检。
- 真实 Codex、Cursor、Claude 的完整对话与原生 Hook 投递不能由脚本模拟替代，仍需宿主端验收。
- `.localhost` 在不同操作系统、受管网络中的兼容性，以及命名代理的长期 CPU、内存和磁盘负载，需要持续环境基准。
- 任意脚本在运行中写出声明范围之外的文件，目前只能要求 Agent 在归档时复核，尚无通用、跨平台的完整文件系统追踪。
- 旧 Map-only Cloud Sync 与多 worktree 的迁移联调仍不能代表新的私有 Main/Session 记忆协议已部署。

这些限制不会被绿色 CI 隐藏；对应条目保留在 `CI_todo.md`，并明确“脚本测试”和“真实宿主验收”的边界。
