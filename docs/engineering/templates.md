# 最小证据模板

阶段五配套。复用同一份任务/PR 内容，不要求新增一组重复文件。详细规则见 [流程](README.md)。删去不适用的栏目前先写理由；不能把未测填成通过。

## 任务与 PR

```markdown
## 目标与范围
- 请求/问题：
- 已观察事实与预期：
- 验收条件（可观察）：
- 不做什么：
- 影响模块/节点、关联公开 issue：
- 基线 SHA / 风险等级与理由：

## 方案
- 选择及原因；R2/R3 关联设计决定：
- 公开接口、持久格式、权限或依赖变化：
- 兼容、失败与恢复考虑：

## 验证
| 验收条件 | 测试/人工步骤 | 源码 SHA / 环境 | 实际结果 | 证据或未测原因 |
|---|---|---|---|---|
| ... | ... | ... | passed / failed / not-run / N/A | ... |

- npm test 结果：
- 附加浏览器/包/宿主验收及适用性：
- 已知缺口与 CI_todo 位置：
- 首次失败、重试与最终结论（如有）：

## 审查与交付
- 自检 / 独立 Review：分别说明人或角色、范围、准确 head
- Required 对应 head 与链接；合并 SHA：
- 安装/运行/部署/npm：分别说明结果或有依据的 N/A
- 待办和剩余风险：
- 私有协议任务的归档/关闭：仅保留允许公开的摘要，不粘贴私有回执
```

未创建 PR 或未合并时就写尚未执行，不预填成功。公开证据不包含用户消息全文、密钥、真实 Session 路径/标识或内部服务器信息。

## 重要设计决定

放入现有设计文档或必要时新增 `docs/design/<topic>.md`；不强制连续编号，不为避免编号冲突添加全局注册表。

```markdown
# 决定：<简短标题>
- 状态：proposed / accepted / superseded / deprecated
- 日期、关联任务/PR、适用版本：
- 背景与约束：
- 候选方案（包括不改）及依据：
- 选择与代价：
- 接口/数据/权限影响：
- 验证和失败恢复：
- 替代/被替代关系：
```

## 运行变更与复盘附加项

仅在适用时补充：执行授权和负责人、目标版本/制品校验、影响范围、部署顺序、观察指标与时间/样本条件、停止条件、恢复方法及其验证状态。阈值必须按任务确定，不能空填“正常”。

复盘记录：影响、事件时间线、已证实成因/未知项、现有检查为何遗漏、实际恢复结果、改进项负责人/验收条件。未获得负责人接受的任务标待分配，不能视为已落实。
