# 开发流程规范

阶段四：本项目从需求到运行反馈的统一流程。依据与取舍见 [采纳表](adoption.md)，历史审查见 [现状](baseline.md)。日常只读本页与本次涉及的专项，不要求每个 Agent 重读全部外部资料。

## P00 适用与风险

本页在合并 Main 后作为仓库开发流程执行。分支/安全/记忆权限以 [RULE](../../RULE.md) 和相关专项契约为准；不能用模板或外部文章覆盖授权。现有代码不因此宣称全部合规，新增及本次触及范围逐步落实。

| 等级 | 判断依据，不只看文件扩展名 | 设计与附加验证 |
|---|---|---|
| R0 | 仅非行为性仓库文档，如文字修正、资料索引 | 简短范围说明、引用/链接/命令核对；安装和运行验证按适用范围说明 N/A |
| R1 | 单模块局部行为，未改变公开接口、持久格式或权限 | 复现/验收条件、局部方案、正反用例及受影响回归 |
| R2 | 跨模块、公共接口、构建/分发、重要 UI 流程，或改变开发治理行为 | 简短设计决策、调用/数据边界、公共入口集成、兼容和适用的安装/浏览器验收 |
| R3 | 身份/权限、私有数据、持久格式迁移、并发写入、破坏性恢复或生产发布 | 明确批准边界、数据不变量、失败/并发/重放与恢复验证，发布负责人和停止条件 |

按最高受影响风险定级；未知权限或数据影响先按 R3 分析再收敛。**所有级别仍执行现行 `npm test`、安全检查和完整 Required；分级不启用 CI 跳过。** 治理文档改变权限/门禁时可能是 R3，不能标 R0 来豁免审查。

## 全流程

步骤编号用于定位规则，不要求串行等待：P04 的测试设计从 P02 开始，与 P03 的实现一起迭代；P06 可以在 CI 运行期间开展，但 P07 合并必须等所需证据完成。

| 步骤 | 输入 | 责任与动作 | 出口证据 / 未满足时 |
|---|---|---|---|
| P01 需求就绪 | 用户请求、事实与当前基线 | 开发者澄清结果、范围、风险；需求负责人解决业务歧义 | 可观察验收条件、非目标、模块/节点定位或未知项；阻塞性歧义未解不做不可逆实现 |
| P02 设计 | 验收条件、调用方、现行契约 | 开发者比较最小方案；跨边界决策交 Reviewer，授权问题交有权人 | 必要的决策、兼容/恢复/验证计划；未证实的假设先隔离实验 |
| P03 实现 | 已确定范围与方案、最新 Main 平台分支 | 开发者按已有模块职责实现，同时补正式回归 | 一个完整意图的差异；不能混入无关重构、个人配置或临时实验 |
| P04 测试设计 | 行为差异、风险和旧缺陷 | 开发者建立断言；Reviewer 挑战漏测和错误预期 | 验收条件对应测试/人工步骤，标明盲区与执行入口 |
| P05 本地验证 | 准备交付的准确源码、测试与环境 | 开发者先定向、后总入口，必要时附加浏览器/包验证 | 命令、环境、退出码与结果；失败先诊断，不删断言求绿 |
| P06 Review | 完整 diff、测试证据、设计依据 | Reviewer 核对正确性、风险、复杂性及测试；作者处理意见 | 阻塞问题解决；自检与独立审查分别标注，不能冒充签字 |
| P07 PR/合并 | 同步最新 Main 的准确 head、审查结果 | 开发者执行现有 PR 流程，检查可信 CI 与目标 SHA | Required 和当前保护条件满足才合并；变更 head 后重新核验 |
| P08 验收/发布 | 合并提交、对应制品、适用批准 | 实施者做范围内合并后验收；发布负责人执行现有发布/部署手册 | 合并、安装、运行、npm、部署分别给出事实；未获生产授权不发布 |
| P09 收口 | 验收结果、剩余问题、归档回执 | 开发者对照验收表，维护待办与相应记忆 | 每项通过或有依据 N/A；关键项未测保持未完成，准确报告阶段 |
| P10 反馈 | 运行缺陷、回退或流程失效 | 责任人复盘、形成回归与规则修正 | 防复发措施有负责人/验收条件；不能以“加强注意”代替修复 |

## P01–P02 需求与设计细则

- 输入带节点时核对 ID、含义和版本；未知时沿当前 Map 定位候选模块，再看父级约束与必要关联，不假设目标节点已知，也不一次加载全部记忆。
- 公开源码研究可仅依赖 Git 与公开资料，并声明没有校验私有状态。依赖私有记忆时按 [服务器契约](../../references/server-memory.md) 鉴权读取；不可达就说明，不能退回陈旧本地记录冒充最新事实。
- 需求至少写“谁在什么条件下做什么、应看到什么”，Bug 写复现、实际/预期、影响版本。把推断和已观察事实分开。
- R2/R3 的重要决定写背景、候选方案、取舍、数据/API 兼容、失败恢复和验证；可以复用已有设计文档，只有长期决定才单独留 ADR。
- 文件系统/记忆相关设计必须明确：谁有写权、版本冲突如何处理、写入失败/中断后保持什么状态、重复请求语义、派生索引如何与权威数据一致。不要默认“一个 JSON”或“分层 MD”自动解决并发和检索问题。
- 涉及性能或 Agent 检索，先定义成功率/正确性，再比较耗时和成本。固定数据版本、节点规模、模型参数、工具能力、缓存条件和统计口径；记录失败/重试，不以一次最快结果推广为普遍规律。收费渠道与预算另行明确。

## P03 编码细则

- 沿用 [仓库布局](../repository-layout.md)、既有语言和辅助函数；shared 不反向依赖具体服务。为真实变化建接口，不为假想复用抽象；不跨层读取对方私有实现。
- 新的公共输入验证类型、允许字段、大小与错误语义；JSON 用解析器及既有校验器，不靠文本替换。重命名代码符号不能暗中改变序列化字段或磁盘格式。
- JS ESM 保持当前模块风格，明确 Promise 的等待、拒绝处理和取消归属。Python 精确捕获可处理异常，业务安全校验不用 `assert`；资源用受控生命周期释放。
- 后台任务、定时器、文件句柄、锁和子进程明确创建者、超时/停止机制及退出确认。使用已有跨平台封装；Windows 后台子进程隐藏窗口，不能为测试杀死非本任务进程。
- 错误可传播、转成领域错误或在边界恢复；不得吞掉错误返回假成功。日志保留可定位的错误类别和关联 ID，不重复刷屏或暴露密钥/私有记忆。
- 写路径必须验证范围；避免拼接 shell 处理用户输入。删除/迁移要先验证目标和恢复方案；原子替换与版本冲突使用既有协议，不能自行退化为最后写入覆盖。
- 命名描述业务；注释说明约束、原因和意外边界，不翻译每一行代码。变更同步更新契约；不加无关格式化、冗余作者日期或注释掉的废代码。
- 新依赖说明必要性、维护/许可、最小运行时与跨平台兼容，优先已有依赖。锁文件按包管理器生成，不能顺手升级无关依赖。

## P04–P06 测试与审查

正式规则和入口以 [测试治理](../test-governance.md) 为单一来源。本节只连接风险与证据：

| 风险 | 必须回答的验证问题 |
|---|---|
| 逻辑/校验 | 正常、边界、缺失/非法值是否给出约定结果？旧错误实现是否会使回归失败？ |
| 跨模块/API | 从公共入口到最终可观察状态是否成立？Mock 假设有没有集成证据？ |
| 并发/持久化 | 两个写入者、断线重试、超时/崩溃、陈旧版本和重复请求是否保持不变量？不仅检查退出码。 |
| UI/宿主 | 用户实际路径、刷新/恢复、权限状态是否正确？浏览器模拟不冒充原生客户端验收。 |
| 包/兼容 | 安装的是否是待交付制品？最低运行时、支持系统与旧配置能否使用？ |
| 检索/性能 | 质量门槛相同吗？节点未知的定位成本、模型轮次、输入/输出/缓存 token、端到端时间和实际计费是否分开？ |

测试使用合成数据、隔离目录和本任务进程；不借个人工作台、真实记忆或外部模型补齐普通单元测试。记录随机种子/时间控制。偶发失败保留首次日志与复现条件；重跑通过不能擦除失败，必要时登记负责人和修复条件，不无限重试。

Review 先处理数据损失、越权、行为错误和缺失证据，再看维护性；个人风格建议标为非阻塞。大型变更写清生成物和人工审阅范围。相同 Agent 的第二遍检查仍是自检；没有独立 Reviewer 时如实记录，并按仓库现有保护规则决定能否合并，不能伪造通过记录。

## P07–P09 交付边界

- 使用 [安全流程](../development-security.md) 的暂存区、历史和制品检查。只暂存明确文件；失败、超时、缺对象都不能解释成通过。
- 当前 CI 触发、Required 和发布入口以 workflow 为准；推送分支不等于 PR 已验证，先核对 [发布手册](../npm-release-runbook.md)。不同 head 的检查不能拼成一次成功。
- 合并后核验最新 `origin/main` 包含本次合并。影响分发/运行的改动按 RULE 安装和真实入口验收；纯仓库文档可解释为何不影响制品/运行而标 N/A，但仍验证文档流程和全量门禁。
- npm 发布、Cloud 部署、本机 Skill 更新是不同目标。发布按原手册与授权执行；生产变更先明确可恢复版本、数据兼容、观察指标、停止条件及负责人。没有实际回退演练不能写“回滚已验证”，没有自动化不能写“自动恢复”。
- 业务失败、越权或数据损坏停止扩大影响；保留证据，并按批准方案恢复。紧急修复缩小范围、加快协作，不豁免安全、Required、权限或真实验收。
- 完成证据复用 [模板](templates.md)。遗漏关键验收保持进行中，未完成模块记入 [CI_todo](../../CI_todo.md)。公开摘要不含私有数据，私有归档按服务器契约执行，不把 Git 文档当第二份 Session 记忆。
- `Session 上传`、`Main 基线发布`、`PR 合并`、`用户验收`、`Plan 关闭` 各自需要对应事实。没有挂载协议任务就不伪造 plan-finish；有协议任务也不以本文豁免其服务器条件。
- 只清理确认归本任务且无需保留的临时资源；不得删除共享 temp、其他 worktree 或失败证据。范围/破坏性授权不明确则保留并说明。

## P10 复盘与维护

数据损失、越权、发布回退、重复严重回归或用户明确要求时，形成复盘：影响、时间线、成因、为何现有检查没发现、修复/回归、责任人与完成证据。系统性原因优先，不将责任简化为某人粗心。

公开复盘只含可公开工程事实，私有内容仍留服务器。将通用结论改入所属契约，不把每次经验复制成全局规则。以后每次变更涉及某项规则时检查其命令和自动化是否仍对应；新增门禁先以反例验证，再宣称已强制执行。
