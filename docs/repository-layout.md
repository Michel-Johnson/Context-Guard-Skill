# 仓库文件归属

本表描述当前物理布局，不表示运行代码已迁移。先明确职责，再按依赖和回归证据调整路径。

| 当前位置 | 职责与边界 |
| --- | --- |
| 根目录 README / RULE / CI_todo / SKILL | 用户入口、开发规则、验证状态、Agent 入口；不放实验长文 |
| 根目录 roles / Coordinator / Developer / Tester | 当前角色设计入口；本轮不迁移、不改角色行为 |
| `references/` | 随 Skill 分发的操作契约及角色按需参考；不能依赖未分发文件才能执行 |
| `docs/` | 仓库维护、接口规范和验证说明；`docs/design/` 只放设计讨论与草案 |
| `bin/` | 安装和命令启动入口，不堆业务状态机 |
| `scripts/cloud/` | Cloud 服务、鉴权、服务端记忆及人工验收 |
| `scripts/workbench/` | 本地服务、绑定、宿主投递和同步；目前也混有两端共用协议，第二阶段需审查提取 |
| `scripts/sync/` | 旧 Map-only 兼容入口；删除前核对调用者及迁移路径，不默认继续扩展 |
| `scripts/*.py` | Agent / Hook / Map 工具及开发分支检查；本轮不改 Hook |
| `prototype/` | 实际生产工作台及地图模型，名称是历史遗留；设计画廊与 fixtures 混入问题留待代码阶段分离 |
| `site/` | 官网与交互演示；不成为生产工作台的第二套业务实现 |
| `tests/` | 产品正式回归及显式 helper |
| `.github/`、`.githooks/` | CI/CD 与开发安全；其中产品测试的归位需要同步调整发现和过滤规则 |
| `deploy/` | 服务部署模板，不放凭据与生产数据 |
| `.codex/`、`output/`、`temp/`、依赖目录 | 私有状态、生成物、临时实验及依赖；不进入产品源码和分发包 |

## 第二阶段代码审查顺序

1. 分离正式工作台与设计画廊、演示数据；保持生产页面行为和官网演示可验证。
2. 确认 Cloud / 本地共用的协议和模型，再从宿主目录提取；不能只改目录名而保留职责交叉。
3. 查清旧同步入口的实际调用及测试，删除已被替代的分支；仍有消费者的兼容入口先迁移。
4. 收敛测试与包内容清单的重复维护；保持正式测试、安全检查和分发隔离，不通过删除检查来简化。

Cloud 接口、通信、绑定、心跳与派单作为一个审查范围。Hook 和角色设计的独立改动不在本轮顺带重写。
每阶段独立 PR；文件移动须更新 import、链接、安装清单和测试，运行行为变更须另外验收。

## 分支与工作树

远端分支、本地分支、远端跟踪引用和 worktree 分开清点。已被 squash 合并不一定能用祖先关系判断，需核对 PR 及实际内容。
删除前检查未提交内容、独有提交和仍在使用的工作树；重复 PR 先明确哪份实现被采用。本轮文档整理不删除分支或关闭其他人的 PR。
