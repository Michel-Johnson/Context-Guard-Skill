# 接口、同步、升级与鉴权：讨论清单

当前传输格式草案见 [接口规范 v2](interface-contract-v2.md)；本文保留设计问题，不作为另一套协议。

状态：待讨论，尚未定稿。本文记录产品问题和设计议题，不授权实现，不替代现有接口规范，也不表示相关功能已经完成。

下一步草案：[Session 工作台接口规范 v0.1](session-workbench-interface-draft.md)。新增的明确边界是 Main 只经合并更新、GitHub 与 Cloud 两条合并通道、Cloud 可作为本地 Session 后端的远程前端。具体上传内容仍待决定。

## 一、用户期望

- 更新 Skill 后，工作台应安全切换到兼容版本，不要求用户排查进程或手动处理内部迁移细节。
- 自动通过 Git 远程仓库识别项目，不要求用户填写项目 ID。仓库代表项目，main 代表主线；不同分支和 Session 不应被误认成不同项目。
- 常规连接只需提供云端地址并登录；项目匹配和内部同步凭证由软件管理。有多个远程、fork 或身份歧义时才请求用户选择。
- 在继续迭代前，先共同明确模块接口、数据同步、版本兼容和权限边界。

## 二、模块接口

### 需要解决的问题

- 工作台、Agent、Hook、CLI 是否通过统一入口读写，避免各自修改同一份文件？
- 谁负责数据校验、权限判断、持久化、事件通知和恢复？
- Map、Todo、Bug、用户消息、附件和生成索引，各自的权威来源、归属和读写入口是什么？
- 本地工作台与云端工作台哪些接口共用，哪些必须保留差异？

### 待确定的规则

- 页面负责展示与发起操作；本地服务统一协调本地持久化。具体存储接口仍待设计。
- 每个接口明确调用方、提供方、输入、输出、权限、版本、错误、重试和成功条件。
- 区分源数据与派生索引；索引失效不能冒充源数据已经更新。
- 不在本轮直接确定 URL、字段名称、具体鉴权协议或数据库方案。

## 三、云端与本地同步

### 需要解决的问题

- HTTP/HTTPS 同步代码存在，但连接配置、运行版本与实际同步成功是不同的验收项。
- 旧本地快照可能覆盖较新的云端修改；未上传的记录不能被误解为要求删除。
- 断线、丢回执和冲突后如何继续，而不是永久卡住或重复执行？
- 两端同时修改、删除父节点同时修改子节点、附件先后上传，应如何处理？

### 待确定的规则

- 对选择服务器记忆模式的项目，云端为权威来源，本地为工作副本、版本缓存和待上传队列；不强制所有项目必须联网使用。
- 区分“本地已保存”“待同步”“云端已确认”“冲突”“连接失败”。
- 明确新增、修改、删除的语义；缺少字段或文件不自动等同于删除。
- 重复请求安全重试；不相关修改可合并，重叠冲突保留双方数据供处理。
- Session 上传不等于发布 Main。Main 发布需要独立权限和已合并代码的验证。

## 四、版本迭代与兼容

### 需要解决的问题

- 仓库源码、安装的 Skill 和运行中的后台服务可能分别处于不同版本。
- 更新文件不会自动替换已经运行的进程；旧服务可能缺少安全接管需要的身份信息。
- 已有可识别旧版的升级和 legacy 显式备份迁移路径，但用户仍需理解过多内部细节。

### 待确定的规则

- 分别管理发布版本、运行时身份、接口版本和数据格式版本，不把它们混成一个版本号。
- 定义本地与云端的兼容范围、能力检查和不兼容提示。
- 迁移前检查未保存草稿、待上传队列及活动会话，备份后再切换并验证。
- 定义失败恢复流程。数据格式已变化时不能仅回退程序文件就声称完成回滚。
- 保留必要安全检查，同时提供用户可理解的升级入口和结果说明。
- 回归覆盖跨版本升级、进程重启、旧数据读取、迁移中断和恢复。

## 五、用户鉴权与项目识别

### 需要解决的问题

- 网页登录与机器同步目前使用不同授权机制，不能把网站密码直接当作接口令牌。
- 缺少面向普通用户的完整连接引导时，底层项目 ID 与凭证管理被推给用户。
- 仓库地址只能帮助识别项目，不能证明用户有权访问该项目。

### 待确定的规则

- 自动规范化 Git 仓库身份；处理 SSH/HTTPS 地址、仓库改名、fork、多远程和非 Git 项目。
- 登录后，在用户授权范围内自动匹配项目并取得限定权限的同步凭证；首次创建及授权扩大需明确处理。
- 不明文保存网站密码，不在命令行、日志、文档或 Map 中暴露凭证。
- 明确凭证的本地安全存储、有效期、更新、退出和撤销规则。
- 区分普通同步、其他 Session 访问、Main 发布和服务器管理权限。
- 具体采用何种登录交换或设备配对协议，留待讨论，不预先承诺方案。

## 六、后续讨论与验收

建议依次讨论：模块职责与数据归属 → 接口契约 → 项目识别和授权 → 同步冲突规则 → 版本兼容与迁移。

共同验收主线：首次连接 → 本地修改并同步 → 云端修改回到本地 → 断线恢复 → 双端冲突 → 升级后继续使用。

每项决定确认后，补充：适用范围、输入输出、失败行为、兼容策略和对应测试编号。未决定项继续保留，不自动标记完成。

本次只新增讨论文档；不修改实现、不部署、不更改现有接口，也不表示云端连接或同步缺陷已解决。
