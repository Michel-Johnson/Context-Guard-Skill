# Cloud 夸克附件

## 范围与权限

Cloud 人类工作台上传文件，由服务端暂存并转存到共用夸克网盘。附件卡片保留文件名、夸克文件 ID、分享链接和提取码。点击跳转夸克；持有链接和提取码的人可以访问，不受 Cloud 登录权限约束。

分享使用提取码模式及平台的长期有效选项，并不保证永不失效：网盘删除、撤销分享或平台限制仍会使链接失效。移除 Map 卡片不删除网盘文件或撤销分享。

仅已认证的 Cloud 工作台可提交，按项目、Main/Session、Session 代次、节点及稳定 owner ID 绑定。概览页不接受附件，也不显示上传按钮；页面根据 bootstrap 的 `interfaceCapabilities.attachments` 隐藏未配置项目的入口，文件提交函数同样检查。Agent v2 blob 接口和本地附件接口不改变。Cloud 单文件上限为 256 MiB。

## 服务端配置

默认禁用，不隐式读取开发者机器的网盘凭据。管理员须在服务器的专用服务账户下安装、检查并授权固定版本 Quark CLI。安装目录、授权配置、日志和任务记录必须位于源码仓库之外，限制为服务账户可访问，不进入公开制品。

设置以下服务进程变量，然后重启 Cloud：

- `CONTEXT_GUARD_QUARK_BACKEND`：`skill`（默认，官方 Skill）或 `kuake`（第三方独立 CLI）。
- `CONTEXT_GUARD_QUARK_CLI`：已审核的 `scripts/quark-drive.cjs` 或 kuake 可执行文件的绝对路径。
- `CONTEXT_GUARD_QUARK_SHA256`：该 CLI 文件本身的 SHA-256，不是 ZIP 的哈希。
- `CONTEXT_GUARD_QUARK_COOKIE_FILE`：仅 `kuake` 使用，仓库外的 Cookie 原文文件绝对路径。Linux 不允许其他用户读取，建议 root 所有、服务组可读的 `0640`。每次调用重新读取，轮换 Cookie 无需改代码。

`kuake` 后端固定版本验证基于上游 v1.5.0。Linux amd64 发布二进制 SHA-256 为 `a38a80fc506dfb4bb44956566f35459192e5005125cffb8283febe17acfcf681`。独立 CLI 不依赖 Agent 或大模型；Cookie 通过子进程环境传入，不作为命令参数，关闭 `.env` 自动加载及调试。其工作目录位于私有数据目录的 `quark-cli/`。不向子进程传递 Cloud/模型凭据。

该第三方工具不是夸克官方 SDK；接入前需审查其许可证与适用场景，不能承诺接口或 Cookie 永久有效。网盘上传采用随机唯一名称，Map 保留原文件名；任务同时保存真实文件 ID 与远端路径，分享前核对身份。只对只读 `info` 的 `FILE_NOT_FOUND` 最多补查三次（间隔两秒），不自动重发上传或分享。分享参数为 `0 true`，即长期有效且需要提取码。

启动时校验哈希，不匹配则拒绝启动。Cloud 不安装或自动更新第三方程序，不提供经 HTTP 修改 CLI 路径或传入任意 CLI 参数的接口。CLI 以服务器服务账户运行；不要直接复制个人设备的授权配置。服务进程只调用 upload/share，不发送对话原文、真实 Session ID 或质量追踪参数；第三方 CLI 自带的设备/操作遥测并未全部禁用。

**宿主限制：** 1.0.20 CLI 会识别 Agent 环境；普通无 Agent 标识的进程实测返回 `-104`，拒绝使用。本地验证运行于真实 Codex 宿主，不代表普通 Linux/systemd 服务兼容。适配层仅透传真正存在且值为 `1` 的 `CODEX_ENV`、`CODEX_SHELL`、`CODEX_CI` 标识，不伪造身份，不转发会话 ID、Cloud 密钥或模型凭据。生产必须先确认夸克支持的服务端/Agent 托管方式；不要手填标识绕过限制。未取得受支持的服务器授权方式前不能宣布可直接上线。

生产启用前必须验证该服务账户的上传、下载内容校验、受提取码保护的分享，以及 Cloud 页面实际上传。开发机授权和替身测试不能代替生产验收。

生产状态（2026-09-13）：`638acd3d` 已部署固定 kuake v1.5.0 后端。服务账户下的生产 Cloud HTTP/Map 验收完成合成 PDF 上传、ready 卡片持久化、受提取码保护分享、下载 SHA-256 一致及测试卡片清理；外部分享页返回 HTTP 200。浏览器交互由同一合并提交的自动化覆盖，尚未将生产人工拖放另行登记为已执行。服务器上存在一个上线前即引用已删除提交的历史 Session，自动 Main 发布会对该 Session 继续失败关闭；它与附件链路无关。

## 持久流程

任务及暂存文件位于 Cloud 私有数据目录的 `attachments/`。浏览器把原始文件作为 HTTP 请求体发送，不转换 Base64，也不把整份文件读入 JavaScript 内存。服务端边接收边计算 SHA-256 并写入唯一临时文件；完整接收且通过单文件与总配额检查后，才原子移动到任务暂存目录。失败、取消和超限请求会删除未完成的临时文件。随后写入 Map 占位卡片，依次上传、保存文件 ID、创建分享、保存分享引用、提交 Map 完成卡片。只有 Map 提交成功后才清理正式暂存文件。

- 同项目、视图、代次和 upload ID 重放复用任务；同 ID 携带其他内容或 owner 拒绝。
- 分享失败后重试复用已保存的文件 ID；Map 提交失败则保留分享引用和暂存文件。
- 重启继续已确认阶段；上传中断且没有可靠文件 ID 时，标记结果不确定，停止自动重传，交管理员核对。当前不提供自动远端对账或修复不确定任务的管理接口。
- 节点/owner/附件被删除后不重新创建；换 Session 代次后停止旧任务回写。已发出的网盘请求无法由删除卡片撤回。
- 单进程按队列处理，跨操作使用文件锁；不支持多个 Cloud 实例共享同一网盘 CLI 授权目录并并行处理。
- 单文件上限 256 MiB；已登记且未完成文件总量上限 512 MiB、任务记录上限 10000。额外最多并发接收四份文件（接收区最多约 1 GiB），超出返回 503。达到限制后拒绝新上传并保留既有记录。启动清理接收区未提交的残片；失败的正式任务仍保留。反向代理必须允许至少 256 MiB 请求体；如需真正端到端流式传输，还应关闭该路由的请求缓冲。无自动删除失败文件或历史任务策略。磁盘容量告警和人工清理仍属部署运维责任。
- HTTP 请求接收总时限十分钟、无数据传输超时十五秒、请求头超时十五秒。浏览器同样设置十分钟上限，可在接收阶段取消。
- 接收完成后的网盘上传独立限时三十分钟；查询与分享仍限时两分钟。网盘上传超时仍标为结果不确定，保留暂存和记录，不自动重传。
- 重试为人工触发；长时间授权失效不会无限循环请求网盘。页面退出不取消已接受的任务。
- Map 写入的版本冲突或明确可重试的 `STATE_BUSY` 最多尝试四次，锁忙时递增短暂退避；恢复保护锁等错误仍失败关闭。这一重试不包裹网盘上传或分享，不改变未知上传停止重传的规则。
- 后台失败保留私有 `lastFailure`（阶段、白名单错误类别、时间），成功重试也不抹掉该证据；不保存原始供应商报错、Cookie 或签名 URL。历史任务没有此证据时，不能将一般失败提示当作确定根因。
- 浏览器在上传被接受、重试被接受后主动读取当前视图，仍遵守草稿与版本冲突保护；重试等待及错误显示在原附件旁，不依赖一次 SSE 推送。异步返回不得写入已切换的项目或视图。

## HTTP

所有路径位于 `/api/workbench/projects/<project>/api/attachments`，沿用工作台 Cookie/Bearer 鉴权及 `?view=main|session:<id>`。

- `POST /`：`Content-Type: application/octet-stream`，请求体为原始文件字节（包括 JSON 文件）；`X-Context-Guard-Upload-Id`、`X-Context-Guard-Node-Id`、`X-Context-Guard-Owner-Kind`、`X-Context-Guard-Owner-Id` 和 URL 编码后的 `X-Context-Guard-File-Name` 承载元数据。返回 202 和任务状态。旧 JSON/Base64 封装不再接受，旧页面须刷新。私有目录路径与凭据不返回。
- `GET /<id>`：读取所属视图任务，不允许跨项目/视图读取。
- `POST /<id>/retry`：重试确定失败；上传结果不确定返回 409，不盲目重复上传。
