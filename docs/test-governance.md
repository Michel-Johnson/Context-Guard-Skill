# 测试治理规范

本规范解决一个具体问题：不同 Agent 可以编写不同功能，但测试入口、最低质量和交付证据必须一致。测试清单由 `tests/test-manifest.json` 管理，`npm test` 会先校验清单，再运行测试。

## 谁负责测试

- 开发 Agent 必须为本次改动补单元测试、接口测试和已知回归测试；不能把“补测试”留给别人。
- 独立 Review/CI 只负责找遗漏、挑战测试质量和验证门禁，不替开发 Agent 补齐最基本测试。
- 跨模块功能必须至少有一条从公共入口出发的集成测试。只验证被修改函数不算完成。
- 浏览器真实操作、真实宿主 Hook 和跨平台差异属于验收测试；无法在普通 CI 稳定执行时，必须写进 `CI_todo.md`，不得声称已经覆盖。

## 分层与入口

1. `*.test.mjs`：默认使用 `node:test`，由 `.github/scripts/run-node-tests.mjs` 自动发现。
2. 独立套件：只有需要独立进程、特殊依赖或“失败立即停止”的测试才能列入清单，并写清命令和原因。
3. Browser E2E：由 `npm run test:browser` 运行，覆盖核心用户路径、并发页面和恢复路径，不重复所有单元测试。
4. 包与客户端验收：从实际 npm 包执行，验证安装边界和三种宿主的无对话兼容。
5. `site/`：是独立依赖包，必须提供自己的 `npm test`，由主 CI 的 site job 执行。

## 编写规则

- 一个测试只说明一种可观察行为，名称写“条件 + 结果”。
- 禁止提交 `.only`。跳过测试必须有明确名称/原因，并且不能把关键路径永久跳过。
- 测试必须清理自己创建的进程、端口和临时目录；子进程在 Windows 上必须隐藏窗口。
- 不读取开发者个人目录，不依赖已经运行的工作台，不修改真实项目记忆。
- 回归测试要先证明旧实现会失败，再证明修复后通过；不能只断言函数“没有抛错”。
- 时间、并发和崩溃测试必须检查最终持久状态，不能只检查进程退出码。

## Review 收口

PR 的唯一 Required 状态必须汇总安全、功能、最低运行时、安装、浏览器、客户端和站点检查。Reviewer 还要检查：

- 新接口是否有正常、错误和重试/幂等路径；
- 跨模块改动是否有公共入口测试；
- 测试是否可能在错误实现上仍然变绿；
- 未自动化部分是否已经进入 `CI_todo.md`；
- 测试文件是否被自动发现或在清单中说明例外。

CI 变绿只表示清单中的自动检查通过，不等于测试设计一定正确。重要功能合并后仍需定期做独立测试 Review；高成本真人式 E2E 保留在发布前和定期回归，不要求每个小提交运行。
