# Coordinator 需求讨论

文档版本：v0.1.0。状态：设计已确认，实施与验收进行中。

目标：用户在 Map UI 或 Slack 用自然语言聊清需求。Coordinator 回复简短、自然、抓重点；不要求用户填写需求表或内部 ID。

## 交流流程

1. 探索需求：读取项目说明、节点描述和必要资料，提出有用的追问；未绑定时也能查询相关模块。
2. 推荐归属：展示项目根节点到候选节点的完整路径、各级描述和推荐理由。人类确认后才绑定；暂不绑定时继续讨论。
3. 读取背景：读取根、各级祖先和当前节点的全部记忆正文，每份在固定背景中只注入一次，不随每轮重复添加；聊天中原有工具回执不改写。其他模块按需读取。
4. 连续讨论：先回答当前问题，区分补充、改变需求和旁支探索。回顾的频率与形式根据真实使用调优，不要求每轮附带。
5. 形成需求说明：整理目标、范围、约束、验收条件和未决问题，供人类纠正或确认。

TODO、Bug 都只绑定一个最主要的节点。首次绑定、改绑及创建新节点必须先取得人类同意；涉及其他模块不增加绑定节点。确认归属不代表批准开发，形成说明也不自动派发任务。

## 代码保证什么

- 路径和描述来自实际 Map，描述复用 `purpose`；缺失时明确说明，不由模型编造。
- 新输入检查 Main 版本，内容未变则复用；原请求重试使用已接受的快照。改绑替换当前路径背景，旧内容只保留为聊天历史。
- 保存确认回执，重复确认不重复执行，重启后可以恢复。通知失败与绑定失败分别处理，不把已保存的绑定误报为失败。
- 记忆缺失、无权、节点删除及容量不足明确反馈。初版记忆正文总容量为 96,000 字符，超出时不裁切正文、不绕过权限；缺失部分按需读取。
- 保留 `fs-v2.1`、记忆正文格式和现有权限。对话确认属于对话状态，不修改底层文件结构，不创建执行 Session。

共享路径、工作台 UI 和角色提示词属于 Skill；云端模型、对话服务和 Slack 集成属于 Cloud。Cloud 固定使用 Skill 发布包，不维护第二份共享源码。

## 验收

Map UI、Slack 在隔离测试项目中分别用真实模型走完：提出需求 → 查询资料 → 展示候选 → 人类确认 → 加载祖先记忆 → 继续讨论 → 人类改绑 → 形成需求说明。TODO、Bug 均覆盖。

检查实际工具调用、保存后回读、真实模型输入和界面结果；不能只看接口成功或模型声称完成。未确认不能绑定，只有一个主节点，需求说明不自动批准或派发。

重复请求、过期版本、权限、恢复及渠道隔离用正式自动测试补齐。替身测试与真实入口验收分别记录；真实两端未通过前，不宣称流程完成。

“像人、简短、抓重点”和回顾方式留给人工观察，不设文风评分或固定轮数门槛。提示词提炼“说人话”的表达原则，运行时不依赖开发者本机 Skill 路径。耗时单独报告，不用“收到”或表情代替有意义回复。
