# Coordinator 需求讨论

文档 v0.1.0，设计已确认，实施/验收进行中。Map UI / Slack 自然语言讨论，简短抓重点，不让人填表或内部 ID。

## 交流流程

1. 读项目/节点及必要资料，未绑定也可查相关模块。
2. 推荐唯一主节点，展示项目根到节点完整路径、各级描述/理由；首次/改绑/新节点人确认，暂不绑定可继续聊。
3. 根、祖先、当前节点记忆全文每份只注入固定背景一次；其他模块按需，聊天已有工具回执不改。
4. 先答当前问题，区分补充、变更与旁支；回顾依真实使用调优，不每轮附带。
5. 形成目标、范围、约束、验收和未决问题，交人纠正/确认。

TODO/Bug 均只绑一个主节点，跨模块不增加绑定；归属确认非开发批准，说明不自动派发。

## 代码保证什么

路径/描述取实际 Map/purpose，缺失明说。新输入核 Main 版本，未变复用；重试用已接受快照，改绑替换背景，旧内容仅聊天历史。

确认回执持久、幂等可重启；通知失败与绑定失败分开。记忆缺失/无权/删除/容量不足明确反馈；初版正文总容量 96,000 字符，超限不裁切/越权，缺失按需取。

保持 fs-v2.1、正文和权限；确认是对话状态，不建执行 Session。共享路径/UI/角色归 Skill，Cloud 固定包消费，模型/对话/Slack 属 Cloud。

## 验收

两端隔离项目用真实模型：需求→查询→候选→人确认→祖先背景→继续→改绑→说明，覆盖 TODO/Bug。核真实工具、保存回读、输入与 UI，不信模型声称或接口成功；未确认不绑，只有主节点，说明不批准开发。

自动测试补重试/过期/权限/恢复/渠道隔离，与真实两端验收分开。人工观察简短自然/回顾方式，不设文风评分或固定轮数门槛；提示不依赖开发者本机 Skill 路径。有意义正文耗时单独报，表情/“收到”不计。
