# 项目与节点记忆撰写规范

文档 v0.2.0。只规定 memory.md 的内容/维护；索引与事项另见 [文件结构](design-memory-filesystem-v1.0.1.md)。

## 什么是记忆

Agent 接手所需当前知识，非完整对话、操作或任务日志。项目记忆首轮概览，节点记忆按模块读取；任务复现、方案轮次与测试留事项，不复制进正文。

## 格式

项目固定六个二级标题，名称/顺序不变：

```markdown
# 项目名称 · 项目记忆

## 目标

## 用户

## 能力

## 协作

## 进展

## 约束
```

节点一级标题为“# 节点名称 · 节点记忆”，二级同序但只保留适用部分，适用未知写“尚未确认”。正文自然段/列表，不逐字段表单或强制编号；来源/时间/历史由系统记，必要日期 YYYYMMDD。

## 各部分写什么

| 部分 | 项目 | 节点 |
| --- | --- | --- |
| 目标 | 问题、成功标准、非目标 | 职责边界 |
| 用户 | 使用者、场景、需求 | 使用者/调用方、需求 |
| 能力 | 已有功能、条件、限制 | 功能、输入输出、条件、限制 |
| 协作 | 模块分工/调用 | 依赖、调用方、传递内容 |
| 进展 | 已验证结果、差距、阻塞 | 同上，仅本模块 |
| 约束 | 人确认的规则/取舍/原因 | 局部行为、兼容与规则 |

跟模块不跟某任务/Session；父级概括分工，不复制子正文，跨模块关系放项目/共同父级，各节点只写自身责任。不替代代码/接口。

## 谁维护、何时更新

人可编辑，Coordinator 整理；Executor/Tester 提实现、独立证据和建议，不覆盖权威正文。目标/需求/规则/人验由人确认，技术能力/进展据同版本代码与验证，不把测试当人验、不让人代核技术事实。职责超批准范围先问。

需求/设计/实现/测试/人验或节点变动后检查；无新信息/错误/过时不改。移动/改名核关系链接，删除保留有效知识，自动更新尚未实现。

## 撰写与保存要求

只写有助理解、决策、防复发的知识；局部放节点，单任务条件放事项。区分要求/计划/实现/测试/验收，未实施非能力，存在差距不改目标迁就。

变更更新原段、合并重复，历史系统留；来源冲突先核，不能覆盖人的新决定。进展仅当前结果/差距，不写流水账/相对日期；日志、调试、秘密留各自私有记录。

保存前读权威版本，经 edit_map/版本校验随 Main 保存；本地仅缓存/草稿，冲突保草稿重核，失败不报成功。本规范不增接口或权限。
