# 项目与节点记忆撰写规范

文档版本：v0.2.0。

本文只规定 `memory.md` 写什么、怎么写、谁来维护。目录、`index.md` 和 Bug/Todo/Idea 文件属于底层结构与事项记录，见 [文件结构规范](design-memory-filesystem-v1.0.1.md)，不是本文的记忆正文。

## 什么是记忆

记忆是 Agent 接手项目所需的当前知识，不是完整对话、操作日志或任务记录。项目记忆说明全貌，用于首轮静态上下文；节点记忆说明对应模块，在处理该模块时按需读取。

项目级内容写项目记忆，模块细节写节点记忆。任务的复现步骤、方案轮次和测试过程留在 Bug/Todo 等事项记录中，不整份复制到记忆。

## 格式

项目记忆固定使用以下六个二级标题，名称和顺序不变：

```markdown
# 项目名称 · 项目记忆

## 目标

## 用户

## 能力

## 协作

## 进展

## 约束
```

节点记忆的一级标题改为 `# 节点名称 · 节点记忆`，二级标题沿用相同名称和顺序，只保留适用部分。适用但未知的内容写“尚未确认”，不编造信息填空。

正文用自然段或列表，不写成逐条填字段的表单，也不要求条目编号。来源、修改时间与历史版本由系统记录，不在正文重复填写；确需展示日期时使用 `YYYYMMDD`。

## 各部分写什么

| 部分 | 项目记忆 | 节点记忆 |
| --- | --- | --- |
| 目标 | 解决什么问题、成功标准、不做什么 | 模块目标与职责边界 |
| 用户 | 使用者、场景、需求 | 使用该模块的人或调用方及其需求 |
| 能力 | 已有主要功能、使用条件和限制 | 具体功能、输入输出、条件和限制 |
| 协作 | 模块分工及整体调用关系 | 依赖谁、被谁调用、传递什么信息 |
| 进展 | 已验证结果、未完成能力和关键阻塞 | 本模块的验证结果、差距和阻塞 |
| 约束 | 已确认的全局规则、取舍及原因 | 必须保留的行为、兼容要求和局部规则 |

节点记忆跟随模块职责，不跟随某次任务或 Session。父节点只概括整体职责与子节点分工，不复制子节点正文；跨模块关系写在项目或共同父节点，各节点只写自己的责任。记忆不能代替代码和接口文档。

## 谁维护、何时更新

人可以直接编辑，Coordinator 负责整理。Executor 提供实现结果，Tester 提供独立验证与修改建议，二者不直接覆盖权威记忆。

目标、用户需求、业务规则和验收结论由人确认；能力、限制与进展依据同一实现版本的代码和验证结果。职责调整须符合批准方案，超出方案先问人；不能让人代替 Agent 核实技术事实，也不能把测试通过写成用户验收通过。

需求确认、方案批准、实现或测试反馈、用户验收、节点结构或正文变化后，Coordinator 检查是否需要更新。没有新信息、错误或过时内容就不改。节点移动或改名时核对关系和链接；删除时只保留仍有效的知识。自动更新尚未实现。

## 撰写与保存要求

- 只写能帮助理解项目、决定下一步或避免重复踩坑的内容。局部要求留在对应节点；仅适用于某次任务的条件留在事项记录。
- 区分用户要求、计划、实现、测试与验收。未实施方案不能写成已有能力；实现不符合要求时写明差距，不修改目标迁就实现。信息不足不强行生成记忆。
- 事实变化时更新原段落，合并重复内容，移除失效说法；历史由系统版本保留。来源冲突先核实，不自行选一个写成定论，也不覆盖人的新决定。
- 进展只写当前结果、差距与阻塞，不写聊天或操作流水账，不用“刚刚”“昨天”等依赖对话时间的说法。
- 不保存无关内容、原始日志、临时调试输出、密码或令牌；详细过程和证据留在各自记录中。
- 编辑前读取权威版本，用现有 `edit_map` 和版本校验保存。文档随 Main Map 版本保存，本地只是缓存或待同步草稿；冲突时保留草稿并重新核对，失败不能报告成功。本规范不新增接口或权限。
