# Coordinator 等待时间实验

## 结果

GLM-5.3 真实请求，两个源码问题，每种策略每题两次，共 20 轮调查和 20 次追问。以下均为服务端完整答案就绪时间，不是页面首字或动画结束时间。

| 策略 | 调查回答均值 | 追问回答均值 | 调查模型调用均值 |
| --- | ---: | ---: | ---: |
| 当前串行 | 33.6 秒 | 34.2 秒 | 6.75 |
| 直接分离执行与接待 | 30.9 秒 | 13.3 秒 | 7.00 |
| 直接分离 + 源码预取 | 11.6 秒 | 16.4 秒 | 1.50 |
| 接待专用规则 | 26.8 秒 | 3.6 秒 | 6.75 |
| 接待专用规则 + 源码预取 | 7.9 秒 | 4.6 秒 | 1.00 |

每行 4 个样本，两个问题等权。统计包括所有完成结果，未按质量筛选最快回答。完成不等于回答正确。

## 方法

- 问题一：我想知道codex这个记忆的底层有哪些文件。
- 问题二：解释 Phase 1 的输入过滤、模型提取、结果存储，并给出源码位置。
- 每轮恢复同一真实会话的提问前 20 条消息，不包含本题以前生成的答案。源码固定为 `e72da2b53805894878023d01949a25a082e0a5cb`。
- 模型、provider 参数、原始执行提示词不变。各组执行端均使用 direct，排除自适应再次分派的影响。
- 第 5 秒提交同一追问：“现在查到什么？顺便告诉我当前源码 commit 的前8位，前面的调查继续。”追问耗时从该追问提交开始计。
- 串行组追问排队；分离组创建固定前缀引用的接待会话。它空闲时不调用模型，程序每 100ms 更新进度 inbox；每次追问读取一个一致快照。
- 不完整的工具调用批次不进入快照，thinking 内容不进入同步数据。接待会话的追问不写入执行会话；16 轮分离实验均通过隔离检查。
- 接待专用规则只针对本次“询问进度和版本”场景：只描述快照，不重新调查；本实验不向它提供调查工具。尚未测试接待端派发新任务、修改任务或取消任务。
- 预取包由程序读取 memory 节点相关文件清单、README 9-26 行、phase1.rs 195-494 行，不包含模型预写答案。每次预取耗时计入调查等待。
- 预取范围由人工选定，尚未验证任意 query 的自动节点路由，也不是自动记忆提炼实验。
- 第一批比较前三种策略，第二批根据失败现象增加接待专用规则；保留两批数据，不将迭代后的规则冒充预先随机分配。
- 每批交错顺序，轮次之间串行执行；同一分离轮次内允许执行和接待并发。供应商缓存未重置，第二批可能受进一步预热和服务波动影响。

## 观察

1. 裸 fork 不是稳定解法。第一批有接待会话重新查源码，把本会话空的后台列表误当作外部任务不存在；一次预取组追问仍用了 37.6 秒。
2. 接待专用规则的 8 次追问均只调用一次模型；等待范围 2.4-10.5 秒。10.5 秒样本保留在均值中，不能承诺稳定 3 秒。
3. 最终组合的 4 次原题回答均只调用一次模型，耗时 6.1、8.1、9.0、8.4 秒；查询轮次的减少比 fork 创建开销更重要。
4. 原题结果由执行会话直接产出，不增加父会话重新总结。这里测量的是后台就绪，不是工作台 UI 投递闭环。

## 质量检查

- 20 轮原题和追问均正常结束；所有追问返回的 commit 前缀正确。
- 对全部回答做了阅读检查，并对照关键源码核查了阶段职责、文件职责和进度。未进行独立盲评，也不声称逐条附加断言已穷尽核验。
- 两个优化组 Phase 1 回答覆盖过滤、模型、数据库结果三个核心步骤；文件题覆盖读写模块和具体文件。不能把这种核心覆盖直接等同于全答案正确。
- 初始引用检查只提取数字行号，漏掉了一个 `line=276-315`。追加的完整 URL 审计发现并记录此错误；后续报告以 `mechanical-audit.json` 为准。
- 第一批 serial 的文件题将 `storage.rs` 说成 state DB 读写；实际该文件重建 `raw_memories.md` 并同步 rollout summary 文件。直接分离组及第二批不预取组也出现同类误述。
- 第一批 serial 的另一文件回答把读路径模板的链接指向写路径模板。链接存在并不代表支持所述结论。
- 第二批不预取组的一次接待回复仍复述了 README 中过时的 `core/src/memories/` 路径。即使只读快照，模型仍可能把文档陈述当成已验证的实现事实。
- 第二批预取组合未在本次核心要点核查中发现遗漏，引用 URL 机械检查通过；仍存在版本细节表达不够严谨、回复偏长的问题，不能据此宣称通用质量不下降。

## 建议

优先采用“独立执行 + 只读接待快照 + 版本绑定的相关证据预取”。接待层只接待追问，不重新执行原题；源码事实与操作进度分开，文档内容不能自动晋升为已验证结论。

下一步先补任意 query 路由、陈旧/冲突记忆、任务改向、结果投递和质量盲评。未通过这些验收前，不替换正式工作台。
