## 这是哪类活

本仓库怎么开发。每次开工先看本页。main 保留正式 CI/CD 自动化测试，不带临时测试和假仓；npm 安装包不包含任何测试或开发残留。

## 怎么走

1. **改产品**（工作台、skill、`scripts/` 里的产品命令、文档）：只在产品分支。现在是 `cursor/map-web-f54e`（已与 main 对齐）。做到一段再合进 **main**。
2. **写临时测试、用假仓**：切到测试分支 `cursor/test-layout-f54e`，先把产品分支合进来，再只改 `tests/`。假仓放 `tests/eval/`。
3. **测试里发现问题**：回到产品分支修，不要在测试分支上改产品代码。修好后再把产品合进测试分支复测。
4. **测试分支不合进 main**，也不合回产品分支。
5. **正式自动化测试随产品维护**：用户已明确保留 `tests/ci-smoke.mjs` 和 `.github/` 中的 CI/CD。`scripts/branch_guard.py` 对正式测试设显式白名单，其余临时测试/假仓仍不进 main。`package.json.files` 与打包合同保证它们不进入 npm 包。

## 命令

- 测前：`git checkout cursor/test-layout-f54e && git merge cursor/map-web-f54e`
- 卡住乱提交：`git config core.hooksPath .githooks`（一次），之后 `git commit` 会跑 `scripts/branch_guard.py`
