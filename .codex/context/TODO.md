# 第一版之后的 To-Do

第一版已经锁死：会话、坏例、任务、地图。下面这些现在不做，以后单独开。

## 1. 首次建图（最难，也最要紧）

人第一次把已有仓库变成地图。人在工作台里看图、点头，不在命令行里确认。现在工作台里的「分析」还是演示，没有真的读仓。这一项以后单独做。

已经定的拆法：

- **和人实时商量**，不要一次倒完整棵树。
- 先给第一层：**几种分类方法**，或一批候选模块（可以先多一点）。人和 Agent 看完、想完，再决定第一层怎么切。
- 第一层定了，再拆第二层、第三层，一层一层往下。
- **易读优先**：每张卡的标题和那一句用途，要让人几秒内知道这是啥。空壳口号、看不懂的缩写、一文件一卡，都不算过。

定稿的第一层仍是确认门（大约 4–8 张），那是商量之后的结果，不是一上来就摊开的终稿。

怎么测、怎么验收（就在现在这套 Cloud Agent + 工作台里做，不要做回测试中台）：

这个功能的核心是「商量」和「卡好不好认」。`npm test` 过不了易读这一关；命令行点头也不算验收。分三层，一层过不了就停。

1. **硬错（脚本就能抓）**  
   拷一份没有活地图的夹具仓（Harbor 或 OpenClaw 夹具，把 `map.json` 拿掉或标成未建图）：
   - 第一轮必须先给几种第一层拆法或一批候选，不能直接倒出整棵树
   - 人还没定第一层之前，地图里不该出现完整的第二层、第三层
   - 定稿后第一层大约 4–8 张；每张有标题和一句用途；第一层不能是文件名
   - 状态是「待确认」，等人在工作台点头才变成「已建图」
   对照方式学 OpenClaw 检索那次：给受试 Agent 一份无图夹具 + 说明书，看转写里会不会一上来倒树。那是做功能时的对照，现在先不写。

2. **工作台（浏览器点一遍）**  
   从仓库根起 `python3 -m http.server`，打开 `prototype/workbench.html`。Agent 在这台机器上用浏览器点：第一页只有定稿的第一层、待批有绿点、点进一张只看到下一层。这和现在改工作台时的验法一样。你自己电脑上用 GitHack 或本地服务看同一页。

3. **你点头（真正的验收）**  
   你看卡名能不能几秒看懂、第一层切法你同不同意。这一项没有自动绿灯。人设计测试、Agent 只提草案。


## 2. 优化检索

多查时不要连跑 N 次 `jump`。慢的是每次起 Python（OpenClaw 夹具一次子进程约 26ms），不是文件数量。

已经做的：

- 真 Agent 难任务对照见 `fixtures/openclaw/eval/REPORT.md`：**只靠索引最干净**（约 1 分钟、10 次 Read）。Grep / `jump --json` 都会额外扫盘；只跟链接会迷路。
- Agent 主找法锁定为小索引：`owns-index.json` / `bugs-index.json` / `tasks-index.json` / `sessions.jsonl` 末尾，再打开命中的 Markdown。`jump` 留给脚本。
- 计时见 `fixtures/openclaw/JUMP-SPEED.md`。

## 3. CI/CD 测试（第五块）

第一版没有这一块。以后可能作为第五部分：改完代码怎么自动验、失败怎么回到坏例。

现在明确不做：测试中台、功能链、Stop-hook 门禁。仓库里那套旧 CLI 和 BC 脚本已经删掉，不要再加回来。

做的时候要接上现有四块：测试失败 → 坏例索引；常跑的验法 → 任务说明书里的命令；不要另做一本平行登记册。
