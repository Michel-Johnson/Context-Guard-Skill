# 底层：每次会话记什么、怎么存、怎么找

这里只谈磁盘，不谈工作台怎么点。

一条记忆挂多张卡，等真遇到再做。

## 已定：三个仓库

每次会话固定记 3 样：人这轮说了什么（含文件/图片路径）；这轮的 bug 和修法；Agent 这轮干了什么（一轮一份摘要）。太长只留摘要。密钥不写。

分三个小仓库，不写成一本日记：

1. **会话**：人的话 + 这轮摘要  
2. **坏例**：一条坏例一份 + 关键词表  
3. **地图**：软件怎么拆、文件归哪（拆法变了才写）

## 当前项：每种写成什么文件（未决）

```
.codex/context/
  sessions.jsonl     每次会话往末尾加一行
  sessions/某次.md   只有这轮原文太长、或有附件路径时才建
  bugs/B20.md        一条坏例一份
  bugs-index.json    关键词 → 坏例编号
  map.json           软件怎么拆
  owns-index.json    源码路径 → 哪张卡
  cards/N21.md       一张卡一份，从地图复印出来
```

| 仓库 | 存的形式 | 格式 | 何时写 |
| --- | --- | --- | --- |
| 会话 | 只追加，不改旧行 | `sessions.jsonl` 一行一个 JSON；太长另放 `sessions/某次.md` | 每轮结束必写一行 |
| 坏例 | 按编号覆盖更新 | `bugs/B20.md` 短文；`bugs-index.json` 关键词表 | 这轮出现或改了坏例才写 |
| 地图 | 整图一份 + 复印小卡 | 已有 `map.json` / `owns-index.json` / `cards/` | 拆法或归属变了才写 |

会话一行：

```json
{"id":"2026-08-26-a","human":"三个仓库分类没问题","agent":"把分类收成约定","files":[".codex/context/record-protocol.md"],"bugs":[]}
```

坏例关键词表一行：

```json
{"B20":{"title":"检查器被顶栏盖住","keys":["检查器","灰色","顶栏"]}}
```

坏例正文几行：现象、触发、根因、修复、守卫、证据路径。

下一轮怎么找：报 bug 打开关键词表，只读命中的那一两个坏例文件；改某个源码打开路径表，只读那张卡；问上次说过什么，只看会话文件末尾几行。不要把整张图或全部历史一次读进来。
