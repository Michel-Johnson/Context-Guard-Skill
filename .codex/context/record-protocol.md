# 底层：每次会话记什么、怎么存、怎么找

状态：未决。这里只谈磁盘，不谈工作台怎么点。

一条记忆挂多张卡，等真遇到再做。

## 每次会话固定写 3 样

1. 人这轮说了什么、给了哪些文件/图片
2. 这轮碰到的 bug（修好没修好都记），以及怎么修的经验
3. Agent 这轮干了什么（一份摘要，不是每一句回复一份）

太长只留摘要。图片/文件只记路径。密钥不写。

## 三个小仓库，不要写成一本日记

```
.codex/context/
  sessions.jsonl     每次会话往末尾加一行（人话摘要、回复摘要、文件、坏例号）
  sessions/某次.md   只有这轮原文太长、或有附件路径时才建
  bugs/B20.md        一条坏例一份
  bugs-index.json    坏例标题/现象关键词 → B20，给「先查像不像」用
  map.json           软件怎么拆（不是每次会话都重写）
  owns-index.json    源码路径 → 哪张卡
  cards/N21.md       一张卡一份，从地图复印出来
```

| 记什么 | 存的形式 | 格式 | 何时写 |
| --- | --- | --- | --- |
| 人的话 + Agent 这轮摘要 | 只追加，不改旧行 | `sessions.jsonl` 一行一个 JSON；太长另放 `sessions/某次.md` | 每轮结束必写一行 |
| 坏例 + 修的经验 | 按编号覆盖更新 | `bugs/B20.md` 短文；`bugs-index.json` 关键词表 | 这轮出现或改了坏例才写 |
| 软件怎么拆、文件归哪 | 整图一份 + 复印小卡 | `map.json` / `owns-index.json` / `cards/` | 拆法或归属变了才写 |

`sessions.jsonl` 一行长这样：

```json
{"id":"2026-08-26-a","human":"要记query、坏例、回复摘要","agent":"改了协议稿","files":[".codex/context/record-protocol.md"],"bugs":[]}
```

坏例正文仍是几行：现象、触发、根因、修复、守卫、证据路径。

## 下一轮怎么找（先打开小索引，再打开 1–2 个文件）

1. 人报了个 bug / 报错 → 打开 `bugs-index.json`，命中则只读那一两个 `bugs/*.md`
2. 在改某个源码 → 打开 `owns-index.json`，只读那张 `cards/`（需要时再读它上面几层）
3. 问「上次说过什么」→ 只看 `sessions.jsonl` 末尾几行，或按词搜这一文件；不要把历史原文全贴进来

禁止：把整份 `map.json`、全部 `sessions/`、全部坏例一次读进下一轮。
