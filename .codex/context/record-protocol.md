# 底层：每次会话记什么、怎么存、怎么找

这里只谈磁盘，不谈工作台怎么点。

一条记忆挂多张卡，等真遇到再做。

## 已定：三个仓库

每次会话固定记 3 样：人这轮说了什么（含文件/图片路径）；这轮的 bug 和修法；Agent 这轮干了什么（一轮一份摘要）。太长只留摘要。密钥不写。

分三个小仓库，不写成一本日记：

1. **会话**：人的话 + 这轮摘要  
2. **坏例**：先查目录，再打开对应经验  
3. **地图**：软件怎么拆、文件归哪（拆法变了才写）

## 当前项：坏例目录 vs 经验正文（未决）

坏例文件夹只当**索引**。怎么修、动了哪些代码，另放经验库。还是三个大类，坏例这一类内部拆两层。

```
.codex/context/
  sessions.jsonl        会话目录（每轮一行）
  bugs-index.json       关键词 → 坏例编号（先查像不像，只打开这一份）
  bugs/B20.md           索引卡：标题、现象一句、状态、指向哪份经验
  fixes/B20.md          经验正文：怎么修、怎么防、动了哪些文件
  map.json              软件怎么拆；卡上挂短规矩
  owns-index.json
  cards/N21.md
```

查的时候：先打开 `bugs-index.json` → 命中则打开对应 `fixes/B20.md` → 需要看代码再去正文里写的那些源码路径。不要一上来读全部坏例，也不要把源码再抄进经验库。

**代码不进经验库当第二份源码。** 经验里只写：改了哪些路径、改了什么意思、必要时几行关键片段。真代码以仓库里的文件为准，抄一份会过时。

跟某块软件有关、不是某个 bug 的短规矩，仍写在地图那张卡上。

会话一行仍只当目录，不堆经验。

## 每种写成什么文件（提案，随仓库一起用）

```
.codex/context/
  sessions.jsonl     每次会话往末尾加一行
  sessions/某次.md   只有这轮原文太长、或有附件路径时才建
  bugs/B20.md        索引卡（标题、现象一句）
  bugs-index.json    关键词 → 编号
  fixes/B20.md       怎么修、怎么防、动了哪些文件
  map.json           软件怎么拆；卡上挂短规矩
  owns-index.json    源码路径 → 哪张卡
  cards/N21.md       一张卡一份，从地图复印出来
```

| 仓库 | 存的形式 | 格式 | 何时写 |
| --- | --- | --- | --- |
| 会话 | 只追加，不改旧行 | `sessions.jsonl` 一行一个 JSON；太长另放 `sessions/某次.md` | 每轮结束必写一行 |
| 坏例目录 | 按编号更新 | `bugs-index.json` + 很短的 `bugs/B20.md` | 出现新坏例 |
| 经验正文 | 按编号更新 | `fixes/B20.md`（修法、防再犯、源码路径） | 开始修或修好时 |
| 地图 | 整图一份 + 复印小卡 | 已有 `map.json` / `owns-index.json` / `cards/` | 拆法、归属或短规矩变了才写 |

会话一行：

```json
{"id":"2026-08-26-a","human":"三个仓库分类没问题","agent":"把分类收成约定","files":[".codex/context/record-protocol.md"],"bugs":[]}
```

坏例关键词表：

```json
{"B20":{"title":"检查器被顶栏盖住","keys":["检查器","灰色","顶栏"]}}
```

坏例索引卡只留：标题、现象一句、关键词、状态、经验文件路径。

经验正文才写：根因、怎么修、怎么防、动了哪些源码路径、证据路径。代码只记路径，不整份复制。

下一轮怎么找：报 bug 打开关键词表，只读命中的那一两个坏例文件；改某个源码打开路径表，只读那张卡（卡上就是还生效的规矩）；问上次说过什么，只看会话文件末尾几行。不要把整张图或全部历史一次读进来。
