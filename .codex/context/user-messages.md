## Durable User Constraints

- Agent 记录，人确认/置顶/丢弃。
- 人在 HTML 里操作，不在 CLI。
- 不做 Test Hub / 功能链 / Stop-hook 门禁，直到工作台交互正确。
- 不要用 `window.prompt` / `confirm`。
- 模块卡只要标题和一句用途。
- Bug 是节点内容，不是子节点。
- 新会话默认很小，不要一次加载全部共享记忆。
- 回复使用中文。
- 之后会话直接打开已有地图，不要每次进来都重拆。活地图在 `.codex/context/map.json`，与节点记忆同一份文件。
- 首次建图需要 Agent 理解架构，不是瞬间出图，也不是目录树。
- 分析粒度必须对齐真实开发单元；空壳三节点没有意义。
- 首次分析先写 architecture.md，再投影到 map.json；L1 只是确认门，数量建议 4–8，按仓库体量定，不要写死成恰好 4 张。根目录只铺 L1。模块一次只展示一层：点进模块只画直接孩子，子模块不展开。开工节点若后面还有开工节点（最多两岔）则默认展开；结构超过两个分支就应该是模块，不是开工节点。一张卡下超过约 8 个文件就要先建子模块。模块下面不能只有一级两个胶囊（Linux node 要先拆连接 / 远程命令 / 常驻）。模块卡只要标题和用途。规则、记忆、Bug 不是节点。不要空壳 CLI / TUI / UI，也不要把文件平铺在 L1 下面。提议模块不要挂锁，锁只表示已确认但当前会话未授权。Agent 第一次生成、尚未人批的模块和开工节点，右上角要有绿点。生产/消费默认不画虚线；打开「关系」后点击节点只高亮相关模块、其余变暗，不进入。点模块在正常视图仍然立刻进入。未修 Bug 用右侧面板列出；点进去只画从根到该节点的链路，不走分级页面。会话在修某条 Bug 时，链路上走电流。
- 记忆、Bug、节点、休眠经验可附文件或图片；只记仓库相对路径，不把二进制写进 HTML，也不弹原生对话框。
- 当前会话尚未授权的节点整卡灰色，不要和已授权的米色模块卡长得一样。
- Agent 提议的节点要更灰、更透明，看起来像草稿，不要画成实心卡片，否则会被当成已经确认的节点。
- 点开 Agent 提议节点时，检查器只留标题、用途、加入/隐藏。已确认节点同样要短：两行用途、必要按钮；记忆/Bug 区块名不用编辑；不要把默认 dirty 显示成「探索中」芯片。Bug 只显示标题；不要面包屑、空附件、架构笔记、只看这条、移出会话。
- 2026-08-25: 检查器不要说明文字。不要写「本地可把粘贴文件… / GitHub 预览不能写盘」、不要「连接本机仓库」那段解释，也不要在检查器里列产出/消费。连接仓库只留在附件行的按钮上。标题和两行用途留下。
