# 开发流程规范

仓库开发从需求到运行反馈的流程；权限、分支、合并、清理和交付以 [RULE](../../RULE.md) 为准。只读本页和本次专项，历史取舍查 Git；模板或外部文章不扩大授权。

## P00 适用与风险

| 等级 | 判断依据 | 附加证据 |
| --- | --- | --- |
| R0 | 不改变行为的仓库文字/索引 | 范围、链接/命令核对；安装/运行 N/A 有依据 |
| R1 | 单模块局部行为，不改公开接口、持久格式或权限 | 复现、方案、正反用例和受影响回归 |
| R2 | 跨模块、接口、分发、重要 UI 或治理行为 | 决策、边界、公共入口集成、兼容及适用安装/浏览器验证 |
| R3 | 身份权限、私有数据、格式迁移、并发、破坏性恢复或生产发布 | 批准边界、数据不变量、失败/并发/重放恢复、负责人和停止条件 |

按最高影响定级，未知权限/数据影响先按 R3 分析。等级不豁免安全、selector、Required 或验收；治理变更不能仅凭 Markdown 扩展名标 R0。仅新增/触及范围逐步落实，不宣称现有代码已全部合规。

## 全流程

P04 从 P02 开始、与实现迭代，P06 可在 CI 期间开展，合并须等全部所需证据。

| 步骤 | 责任与出口 |
| --- | --- |
| P01 需求就绪 | 开发者确认结果、范围、节点与可观察验收，业务歧义交需求负责人；未解不做不可逆实现 |
| P02 设计 | 最小方案、兼容/恢复/验证；跨边界交 Reviewer，授权交有权人，假设先隔离实验 |
| P03 实现 | 按职责实现并补正式回归，不混无关重构、配置或实验 |
| P04 测试设计 | 验收对应断言/人工步骤，标盲区和真实入口 |
| P05 本地验证 | 准确源码，先定向后总入口，记录环境/命令/退出码；失败诊断不删断言 |
| P06 Review | 核完整 diff、风险和证据，解决阻塞，自检与独立审查分别记录 |
| P07 PR/合并 | 最新 main、准确 head、可信 CI；head 变化重新核验 |
| P08 验收/发布 | 由实施/发布负责人按范围和批准验证合并后制品，未授权不生产发布 |
| P09 收口 | 每项通过或有据 N/A；关键未测保持未完成，按实际任务协议归档 |
| P10 反馈 | 原因、回归和责任人/验收条件，不以“加强注意”代替修复 |

## P01–P02 需求与设计细则

- 核节点含义/版本，未知沿当前 Map 定位职责、父级约束和必要关联，不全量读记忆。公开研究可用 Git/公开资料，但须说明未核私有状态；私有读取按 [Cloud 契约](../../skill-reference/design/design-memory-server-v1.1.0.md)，断连不以旧缓存冒充最新。
- 需求写“谁在什么条件下做什么、看到什么”；Bug 写复现、实际/预期和影响版本，区分事实与推断。
- R2/R3 决策保留背景、候选取舍、数据/API 兼容、恢复和验证；优先复用已有设计，创建文档须另经用户批准。
- 持久化明确写权、版本冲突、失败/中断、重试幂等和派生索引一致性；性能/检索先定正确性，固定数据、规模、模型/工具、缓存与统计口径，分开时间、token 和计费，记录失败，收费渠道/预算另行明确。

## P03 编码细则

按 [源码位置](../../AGENTS.md#架构与源码位置) 复用既有模块和跨平台封装：shared 不依赖具体服务，不为假想复用抽象或越层读私有实现。

公共输入验证类型、允许字段、大小和错误语义；用解析器，不暗改序列化字段/磁盘格式。JS 明确等待、拒绝和取消归属；Python 精确捕获异常，安全校验不用 assert。后台任务、锁、句柄和子进程明确创建者、停止/超时及退出确认，不杀其他任务。

错误不吞、不报假成功；日志含可定位类别和关联 ID，不刷屏或泄密。路径/删除/迁移核范围和恢复，避免 shell 拼用户输入，沿用原子写入与版本协议。注释说明原因/边界，依赖说明必要性、许可及兼容，不混格式化、废代码或无关升级。

## P04–P06 测试与审查

入口与测试质量只在 [CI 标准](../ci.md#测试质量与责任) 维护。按影响核：逻辑边界、公共入口到最终状态、并发/重试/崩溃、UI/宿主实际路径、制品/最低运行时，以及质量相同前提下的性能成本。

隔离数据/进程，记录随机种子与时间控制；不用个人工作台或外部模型补普通单测。偶发失败保留首次日志/条件，不能重跑抹掉或无限重试。

Review 先数据损失、越权、行为错误与证据，再维护性；风格意见非阻塞，生成物说明审阅范围。同 Agent 第二遍仍是自检，无独立 Reviewer 如实报告，按现有保护条件判断能否合并。

## P07–P09 交付边界

执行 [RULE](../../RULE.md#6-交付与收口) 和 [发布手册](../npm-release-runbook.md)，不拼不同 head 的绿色检查。npm、Cloud、本机更新分别报告；生产变更明确恢复版本、兼容、观察与停止条件/负责人，未经演练不报回滚已验证。

业务失败、越权或损坏先停止扩大影响、保留证据，按批准方案恢复；紧急修复不豁免门禁。完成证据复用下表，测试缺口进 CI_todo，需求交 Coordinator；不把 Git 文档当本地笔记。

Main 发布、PR 合并、用户验收、Plan 关闭分别核事实；无协议任务不伪造 plan-finish，有任务不豁免服务器条件。私有回执不进入公开摘要。

## P10 复盘与维护

数据损失、越权、发布回退、重复严重回归或用户要求时复盘：影响、时间线、已证实成因/未知项、检查为何遗漏、恢复与回归、负责人及完成证据。公开仅工程事实，私有内容不公开；通用结论改入所属契约，不把每次经验变全局规则。新增门禁先用反例验证。

## 任务与 PR 模板

复用任务/PR 同一份证据，不另建重复文件；未执行不预填成功，N/A 说明依据。

```markdown
## 目标与范围
- 请求、事实/预期、验收条件、非目标：
- 模块/节点、公开 issue、基线 SHA、风险及理由：
## 方案
- 选择/取舍、接口/数据/权限/依赖变化、兼容与恢复：
## 验证
| 条件 | 入口/环境/源码 SHA | 实际结果 | 证据/未测原因 |
| --- | --- | --- | --- |
| ... | ... | passed / failed / not-run / N/A | ... |
- npm test 与附加浏览器/包/宿主验证、CI_todo 缺口：
- 首次失败、重试与最终结论：
## 审查与交付
- 自检/独立 Review、准确 head、Required 链接、合并 SHA：
- 安装/运行/部署/npm 结果或有据 N/A、剩余风险：
- 私有协议归档/关闭：仅可公开摘要：
```

## 重要设计决定

优先已有设计；新草案/版本须用户明确批准主题、用途、范围，按 [RULE](../../RULE.md#3-实现) 命名和存放，模板不是许可。记录状态（proposed / accepted / superseded / deprecated）、日期/任务/适用版本、背景约束、候选含不改、选择代价、接口/数据/权限影响、验证恢复及替代关系。

## 运行变更与复盘附加项

仅适用时补授权/负责人、目标制品校验、影响范围、部署顺序、观察指标/时间/样本、停止与恢复方法及验证状态。阈值按任务确定，不写空泛“正常”；改进项未获负责人接受时标待分配。
